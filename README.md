# 📋 GAS一括コピペデータ自動仕分けシステム (ver 1.0)

外部システムやメール等から1つのセルに一括して貼り付けられたテキスト（改行区切りデータ）をリアルタイムに検知し、適切な複数列へ自動分割・配置するGoogle Apps Script（GAS）ツールです。
ノンプログラマーの現場ユーザーが迷わず安全に使用でき、コードを修正することなく運用をスケールできる「防衛的設計」と「メンテナンス性」を重視して開発しました。

## 🚀 解決できる実務の課題
- **手動運用のコスト削減**: 毎日発生する「システムから台帳への複数項目のコピペ作業」を1回のアクションに集約し、入力業務を大幅に効率化します。
- **データ破損の防止**: 複数行のデータを1項目ずつ手動で転記する際に発生しがちな、コピペ漏れや行ズレによる台帳データの破損を防ぎます。
- **運用属人化の解消**: システムの仕様変更（項目数の増減）のたびにエンジニアがソースコードを修正する手間を排除し、現場主導での運用維持を可能にします。

## ✨ 主要機能と設計の工夫（エンジニア視点）

### 1. 完全自動のイベント駆動（UXの最適化）
- `onEdit` シグナル（シンプルトリガー）を活用し、ボタン操作や手動でのスクリプト実行を一切不要にしました。
- ユーザーがA列にテキストをペーストした瞬間にパース処理が走り、右側の列へリアルタイムに展開されます。

### 2. 強固なバリデーションと視覚的エラーハンドリング（防衛的設計）
- 入力データの行数が、事前に定義された想定項目数と一致しない場合は処理を安全に中断します。
- エラー発生時はメッセージをセルに出力するだけでなく、該当行の背景色を動的に変更（警告色）させることで、現場ユーザーへの視覚的なフィードバックと手戻り防止を両立させています。

### 3. データ揺れ・残骸に対するクレンジング（データの正規化）
- ユーザーがコピーする環境（Webブラウザ、メールクライアント、各種業務システム）によって混入しがちな「前後の全角・半角スペース」「タブ文字」をプログラム側で自動トリム（正規化）します。
- データの末尾に紛れ込む「空改行」による行数誤認を防ぐロジックを搭載しています。
- データの貼り直しや、設定項目数を減らした際、過去のデータ（右側に残った古い文字）の残骸が混ざらないよう、書き込み前に既存の対象領域を動的に一括クリア（お掃除）するロジックを組み込んでいます。

### 4. 設定の外部分離（コードとコンフィグの分離）
- 分割を想定する項目数（`EXPECTED_COUNT`）は、コード内のマジックナンバーとしてハードコーディングせず、スプレッドシート上の「設定」シートから動的に読み込む設計（疎結合）にしています。
- これにより、ノンプログラマーの運用担当者でも、シート上の数値を書き換えるだけで安全に仕様変更へ対応可能です。

## 🛠️ システム構成
- **開発言語**: Google Apps Script (JavaScript)
- **主要API/イベント**: `onEdit(e)`, `SpreadsheetApp`, `Range.setValues()`, `Range.setBackground()`
- **アーキテクチャ**: 設定（Config）シートとデータ処理ロジックの分離

## 📂 フォルダ（シート）構成
- `仕様・使い方`: 現場の作業メンバー向けのマニュアルを内包した、UX向上のためのドキュメントシート
- `データ入力`: メインの作業用画面。A列が入力トリガーエリア、B列以降が自動展開領域
- `設定`: システムの環境変数を管理するコンフィグシート

## 🖨️ ソースコード (コードの一部解説)
※ リポジトリ内の `src/main.js`（または `コード.gs`）を参照してください。
`onEdit` イベントオブジェクトから `range`、`value`、`row` を動的に取得し、実行条件（A列かつ5行目以降）を最小限の負荷で判定するガード節を設けています。また、書き込み処理はセルのアクセス回数を減らすため、配列に格納した上で `setValues()` を用いて一括書き込み（バッチ処理）を行い、実行速度の最適化を図っています。
